⚠ PROTOTYPE v1 — SINGLE-HOTKEY MODEL (SUPERSEDED)
This prototype uses a single-hotkey model with a post-transcription DECIDING state (Enter=type, Tab=plan). The implemented design uses a dual-hotkey model — intent is chosen before speaking.

Alt+Space → dictate → idle → recording → transcribing → typed
Alt+⇧+Space → plan → idle → recording → transcribing → planning → planReady

Obsolete in this prototype: DECIDING state · Enter/T · Tab/P · 8s auto-type · G=Retry in plan preview

The Core UX Insight

After transcription, the user faces one decision: type it at my cursor or build a plan and execute it. This is the entire UX. Everything else serves this moment. The HUD must make this choice feel instant, natural, and never require a mouse.

Transcribed gemini-2.0-flash · 0.8s
"open Slack and send a message to the team channel saying the build is ready"

↑ This appears at bottom-center of screen, ~300ms after recording stops. Auto-dismisses after 8s (types if no input). Escape cancels. Never steals focus from the target app.

UX Design Rules

RuleBehaviour
Never steal focusThe HUD is always-on-top but click-through. It never takes keyboard focus from the target application. Keyboard shortcuts in the HUD work via global key listener, not focus.
Keyboard-first, alwaysEvery HUD action has a keyboard shortcut. Mouse is optional. Enter=type, Tab=plan, R=run, G=retry, Esc=cancel. Learnable in one session.
8-second auto-typeIf user does nothing at the Decision screen, it auto-types after 8 seconds. Countdown shown. Prevents orphaned HUDs.
Escape always cancelsPressing Escape at any state returns to idle. No confirmation. Clean and fast.
Transcription always shownUser always sees what was transcribed before any action. No surprises.
Provider shown in HUDWhich provider and model produced the result is always shown (e.g., "gemini-2.0-flash · 0.9s"). Builds trust and helps debugging.
Plan steps are readableEach plan step shows the action type (in accent colour) and a plain-English description. No JSON exposed to user.
Errors are recoverableAny error (transcription fail, API timeout, type fail) shows a retry button. Never a dead end.
HUD position is configurableBottom-center (default), bottom-right, or top-center. User sets once and forgets.
